## 1. 控制链路与参数位置图

每个参数在整个管线中有精确的物理位置和作用：

```
┌─────────────────────────────────────────────────────────────────┐
│ 第1层：PICO 头部追踪 (pico_bridge, ~50Hz)                      │
│                                                                 │
│  头部四元数 [x,y,z,w]  +  脊柱四元数 (关节[3])                 │
└──────────────────────────────┬──────────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────────┐
│ 第2层：TWIST2 身体相对追踪 (Tracker类)                          │
│                                                                 │
│  q_body_rel = conjugate(spine) × head                          │
│    → 头部相对于身体的旋转                                       │
│    → 身体转、头不动 → identity → 云台不动 ✓                    │
│    → 头转、身体不动 → 头部旋转 → 云台跟随 ✓                    │
│                                                                 │
│  q_rel = q_body_rel × conjugate(q_cal_offset)                  │
│    → 减去初始校准偏移                                           │
│                                                                 │
│  yaw, pitch, roll = YXZ_Euler(q_rel)                           │
│    → YXZ顺序匹配Unity/PICO坐标系                                │
│                                                                 │
│  DZ = 0.5°  ←──── 死角                                         │
│    物理意义：过滤头部自然微颤（< 0.5°）                         │
│    位置：欧拉角提取后、归一化前                                  │
│    调参：云台静止时抖动 → 增大                                   │
│                                                                 │
│  INV_YAW / INV_PITCH  ←──── 方向取反                           │
│    物理意义：舵机安装朝向不同时翻转方向                          │
│    位置：死角过滤后、归一化前                                    │
│    调参：--no-inv-yaw 或 --no-inv-pitch                         │
│                                                                 │
│  归一化：hv = yaw/90, vv = pitch/60                            │
│    YAW_RANGE=90° → 满量程映射到 [-1, +1]                      │
│    PITCH_RANGE=60° → 满量程映射到 [-1, +1]                    │
│                                                                 │
│  输出：(h,v) ∈ [-1,+1] × [-1,+1]                               │
└──────────────────────────────┬──────────────────────────────────┘
                               │  归一化目标值
                               ▼
┌─────────────────────────────────────────────────────────────────┐
│ 第3层：PD 控制器 (PDController类)                               │
│                                                                 │
│  ┌─ JUMP_THRESH = 0.08 (7.2°) ─────────────────────────┐       │
│  │ 物理意义：触发瞬时跳跃的误差阈值                      │       │
│  │ 位置：PD.update() 的第一个判断                        │       │
│  │ |误差| > 0.08 → 跳过PD，直接跳到目标-0.04             │       │
│  │   → 大转角 0 延迟响应                                │       │
│  │   → 跳跃后留 3.6° 给 PD 精细修正                     │       │
│  │ 调参：降低=更灵敏，升高=更平滑                         │       │
│  └──────────────────────────────────────────────────────┘       │
│                                                                 │
│  |误差| ≤ 0.08 → PD 循环：                                      │
│                                                                 │
│  KP = 2.0  ←──── 比例增益                                      │
│    物理意义：追踪力度                                           │
│    位置：PD 输出项 KP × 误差                                    │
│    效果：KP=2.0 → 1°误差产生 2.0°纠正力                         │
│    调参：升高=跟得更紧，可能振荡                                 │
│                                                                 │
│  KD = 0.5  ←──── 微分增益                                      │
│    物理意义：刹车/阻尼力度                                      │
│    位置：PD 输出项 KD × (误差 - 上一帧误差)                     │
│    效果：误差缩小时 → 负输出 → 减速刹车                         │
│    调参：升高=停得更稳，降低=更灵活                              │
│                                                                 │
│  前馈 = 0.3 × (目标 - 上一帧目标)                               │
│    物理意义：预测移动目标的轨迹                                  │
│    效果：头部持续转动时减少跟踪延迟                              │
│                                                                 │
│  PD_CLIP = 0.12  ←──── 每帧位置限幅                            │
│    物理意义：每帧（20ms）最大指令位置变化                       │
│    0.12 × 90° = 10.8°/帧 = 540°/s（50Hz下）                   │
│    位置：PD 输出求和后、位置更新前                               │
│    效果：防止 PD 发出舵机无法执行的指令                         │
│    调参：过高→过冲振荡                                          │
│                                                                 │
│  输出：平滑后的位置 (h,v) ∈ [-1,+1]                             │
└──────────────────────────────┬──────────────────────────────────┘

                               ▼

│ 第4层：舵机指令 (Gimbal类)                                      │
│                                                                 │
│  H_FACTOR = 1024  ←──── 水平映射系数                           │
│    物理意义：归一化值→步数的转换                                │
│    1.0 × 1024 = 1024步 = 90°                                   │
│    公式：(YAW_RANGE/360) × 4096                                 │
│    位置：gimbal.move() 位置计算                                  │
│                                                                 │
│  V_FACTOR = 682  ←──── 垂直映射系数                            │
│    物理意义：归一化值→步数的转换                                │
│    1.0 × 682 = 682步 = 60°                                     │
│    公式：(PITCH_RANGE/360) × 4096                               │
│                                                                 │
│  SPEED = 2500-4000  ←──── 舵机速度                             │
│    物理意义：WritePosEx 速度参数（步/秒单位）                    │
│    2500 ≈ 600°/s, 4000 ≈ 900°/s                               │
│    公式：2500 + 1500 × min(|误差|, 1.0)                        │
│    位置：PD.update() 速度输出                                   │
│    注：> 1000 的值全部超过物理极限 (948°/s)                     │
│                                                                 │
│  ACC = 80  ←──── 舵机加速度                                    │
│    物理意义：WritePosEx 加速度参数（100步/s²/单位）             │
│    80 × 100 = 8000 步/s²                                       │
│    位置：WritePosEx 7字节数据包，地址 0x29                      │
│    效果：控制启停平滑度                                         │
│    ACC=0   → 瞬时响应（可能抖），最高 948°/s                   │
│    ACC=80  → 平衡，约 700°/s                                   │
│    ACC=254 → 非常平滑，速度上限 359°/s                          │
│    调参：升高=更平滑但更慢                                       │
│                                                                 │
│  输出：WritePosEx(ID, 位置, 速度, ACC)                          │
│    → 串口数据包，URT-1 1Mbps                                    │
└──────────────────────────────┬──────────────────────────────────┘
                               │  串口 (TTL)
                               ▼
┌─────────────────────────────────────────────────────────────────┐
│ 第5层：STS3032 内置控制器 (硬件, EEPROM)                        │
│                                                                 │
│  P = 32 (0x15)  ←──── 内置比例                                 │
│    物理意义：舵机电机驱动力                                      │
│    效果：越大=静锁力越强、运动越硬                              │
│    保持默认值                                                   │
│                                                                 │
│  D = 10 (0x16)  ←──── 内置微分（已调优！）                     │
│    物理意义：舵机刹车力度                                       │
│    默认=32 → 刹车过猛 → 振荡                                   │
│    调至=10 → 柔和刹车，不抖动                                  │
│    设置：python run.py --tune-servo（写EEPROM）                 │
│                                                                 │
│  I = 0 (0x17)  ←──── 内置积分                                  │
│    物理意义：静态误差修正                                        │
│    手册警告：非零可能引起抖动                                    │
│    保持 0                                                       │
│                                                                 │
│  DeadZone = 8 (0x1A, 0x1B)  ←──── 死区（已调优！）            │
│    物理意义：位置误差 < 8步 (0.7°) → 电机停转                  │
│    默认=0 → 每个微步都纠正 → 抖动                              │
│    调至=8 → 忽略亚度级误差                                     │
│    设置：python run.py --tune-servo（写EEPROM）                 │
│                                                                 │
│  Torque Enable (0x28)                                           │
│    物理意义：电机电源开关                                        │
│    0=关闭, 1=开启                                               │
│    启动时和 --tune-servo 后自动开启                             │
└─────────────────────────────────────────────────────────────────┘
```

## 2. 完整程序逻辑

### 2.1 启动流程 (python run.py)

```
1. 加载 gimbal_config.json（如存在 → 应用已保存的限位值）
2. 解析命令行参数（覆盖默认值）
3. 初始化 Gimbal:
   a. 打开串口（Windows: COM6, Linux: /dev/ttyUSB0）
   b. Ping 舵机 ID=1, ID=2
   c. 开启扭矩（写 1 到 0x28）
   d. 舵机归中 2048
4. 初始化 Camera（D415，自动降级分辨率）
5. 初始化 Tracker（四元数运算就绪）
6. 初始化 PD Controller（KP=2.0, KD=0.5）
7. 连接 PicoBridge（等待 PICO 数据帧）
8. 进入主追踪循环
```

### 2.2 归中校准（自动，第一帧）

```
1. 读取第一个有效 PICO 帧
2. 如果身体追踪启用且 Spine3 关节可用：
     q_cal = conjugate(spine) × head
   否则：
     q_cal = head（单位偏移）
3. 存储 q_cal 为"正前方参考"
4. 重置 PD 控制器到位置 (0,0)
5. 舵机归中到 2048
6. 设置 cal=True → 追踪开始
```

### 2.3 追踪循环（每帧，约 50Hz）

```
1. 检查外部命令 (tune_cmd.txt)
2. 等待 PICO 数据帧 (超时 0.1s)

3. 收到帧后：
   a. 获取头部四元数: frame.head.rotation
   b. 获取脊柱四元数: frame.body.joints[3, 3:7]（如启用）

   c. Tracker.update():
      q_body_rel = conjugate(spine) × head              [TWIST2]
      q_rel = q_body_rel × conjugate(q_cal)              [减偏移]
      yaw, pitch, _ = YXZ_Euler(q_rel)                   [角度提取]
      若 INV: 取反                                      [安装方向]
      若 |角度| < DZ: 置零                              [死角过滤]
      h_norm = clip(yaw/90 + H_OFF, -1, +1)             [水平归一化]
      v_norm = clip(pitch/60 + V_OFF, -1, +1)            [垂直归一化]

   d. PD Controller.update(h_norm, v_norm):
      err_h = h_norm - current_h
      err_v = v_norm - current_v

      若 |err_h| > 0.08 (7.2°):
        current_h = h_norm - 0.04  [跳跃：瞬时，留3.6°给PD]
      否则:
        output = 2.0×err_h + 0.5×(err_h - prev_err_h) + 0.3×(h_norm - prev_h)
        output = clip(output, -0.12, +0.12)
        current_h += output

      [垂直同理]

      em = max(|err_h|, |err_v|)
      speed = 2500 + 1500 × min(em, 1.0)
      speed = clip(speed, 2500, 4000)

   e. Gimbal.move(current_h, current_v, speed):
      hp = clamp(2048 + current_h × 1024, 0, 4095)     [步数，水平]
      vp = clamp(2048 + current_v × 682, 0, 4095)      [步数，垂直]
      WritePosEx(1, hp, speed, ACC=80)
      WritePosEx(2, vp, speed, ACC=80)

   f. 推送摄像头帧到 PICO（如摄像头启用）
   g. 记录 CSV 日志（如果 --log 指定）
   h. 打印状态（每 20 帧）
```

### 2.4 校准模式 (python run.py --calibrate)

```
对每个舵机（水平 ID=1, 垂直 ID=2）：
  1. 移到 2048
  2. 正方向扫描，每次 40 步
     → 检测堵转（位置变化 < 5步 连续4次）
     → 记录最大位置
  3. 回到 2048
  4. 负方向扫描
     → 检测堵转
     → 记录最小位置
  5. 回到 2048（最终：舵机保持在此位置）
  6. 计算：
     half_range = (max - min) / 2
     offset = 中点 - 2048
     limit = min(half_range / factor, 1.0)
  7. 保存到 gimbal_config.json: {limit_h, limit_v, port, h_id, v_id}
  8. 提示："将摄像头对准正前方，拧紧螺丝，按 Enter"
```

### 2.5 舵机调优模式 (python run.py --tune-servo)

```
对每个舵机：
  1. 读取当前值（P, D, 死区）
  2. 解锁 EEPROM（写 0 到 0x37）
  3. 写 D=10 (0x16)
  4. 写 CW 死区=8 (0x1A)
  5. 写 CCW 死区=8 (0x1B)
  6. 锁定 EEPROM（写 1 到 0x37）
  7. 验证写入值
  8. 开启扭矩（写 1 到 0x28）
```

## 4. 测试策略

### 4.1 速度标定

运行 `python autotune.py` 客观测量舵机在各参数组合下的阶跃响应。测试 100 组 (KP, KD, ACC)，使用 45° 阶跃输入，测量：

- **稳定时间** (ms)：到达目标 ±1° 以内并保持
- **过冲量** (deg)：超过目标的最大偏移
- **得分** = 稳定时间 + 过冲量 × 100（越低越好）

### 4.2 延迟估算

```
系统总延迟 ≈ PICO→PC网络 + 处理 + 舵机运动

PICO→PC (WiFi):        ~5-15ms
帧处理:                 ~2ms
PD控制器:              < 1ms
串口指令:               ~1ms (10字节 @ 1Mbps)
舵机机械 (90°):          ~95ms (ACC=0, 948°/s)
                         ~130ms (ACC=80, ~700°/s)

总计 (90°转角):         ~100-150ms
```

### 4.3 抖动诊断

| 现象 | 根因 | 修复 |
|------|------|------|
| 静止时高频嗡嗡声 | 舵机 D 太高, DZ 太小 | `--tune-servo` |
| 停止后振荡 | KP 太高, ACC 太低 | `--kd 0.8 --acc 100` |
| 随机抽搐 | 接线松动, 电磁干扰 | 检查连接 |
| 缓慢漂移 | 校准偏移 | `echo c > tune_cmd.txt` |

### 4.4 速度 vs 稳定性权衡

```
更快 ←──────────────────────────────→ 更稳

  ACC=0        ACC=50       ACC=80       ACC=150      ACC=254
  KP=3.0       KP=2.5       KP=2.0       KP=1.5       KP=1.0
  KD=0.2       KD=0.4       KD=0.5       KD=0.7       KD=1.0
  948°/s       ~750°/s      ~700°/s      ~500°/s      359°/s
  可能抖       平衡          最优          平滑          非常平滑
```

## 5. 核心设计决策

### 5.1 TWIST2 身体相对追踪

源自 TWIST2 论文：使用 Spine3（胸部）关节作为身体参考系。用户旋转身体但头部相对于身体不动时，云台不转。只有头部相对于身体的旋转才触发云台运动。

```
公式: q_rel = conjugate(spine) × head

场景1: 身体转45°、头不动（相对身体）
  q_spine = rot45, q_head = rot45
  q_rel = conj(rot45) × rot45 = identity → yaw=0 → 不转 ✓

场景2: 身体不动、头转30°
  q_spine = identity, q_head = rot30
  q_rel = identity × rot30 = rot30 → yaw=30 → 转30° ✓
```

### 5.2 YXZ 欧拉角顺序

Unity/PICO 使用 YXZ 旋转顺序。欧拉角提取公式与此顺序匹配。使用错误顺序（XYZ, ZYX）会在 yaw 非零时产生错误的 pitch。

### 5.3 跳跃 + PD 混合架构

大转角（> 7.2°）绕过 PD 控制器，直接跳到目标附近。提供 0 延迟的大转角响应。小转角使用 PD 平滑追踪。

必要性：
- STS3032 可在 ~100ms 内转 90°
- PICO 更新频率 50Hz（每帧 20ms）
- 无跳跃：PD 需 3-4 帧（60-80ms）到达目标
- 有跳跃：瞬时到位，PD 1-2 帧精细修正

### 5.4 直连串口（无 UDP 中转）

早期版本在追踪器和舵机控制器之间使用 UDP 中继服务器，增加网络延迟和复杂度。当前版本通过串口（URT-1）直连舵机，消除中间环节。

### 5.5 1:1 角度映射

舵机因子源自物理分辨率：
```
4096步 = 360°
1步 = 0.088°
YAW_RANGE = 90° → 1024步 → H_FACTOR = 1024
PITCH_RANGE = 60° → 682步 → V_FACTOR = 682
```

精确 1:1 映射：头转 X°，舵机转 X°。

## 8. 常见问题

| 问题 | 诊断 | 解决 |
|------|------|------|
| "Servo X no response" | 电源或接线 | 检查 12V 供电、URT-1 连接 |
| "Cannot open COM port" | 端口错误或被占用 | 检查设备管理器，关闭其他程序 |
| PICO 一直连不上 | WiFi 或 APK | 同网络，PicoBridge 打开，检查 IP |
| 摄像头未找到 | USB 或驱动 | 检查 USB3.0，重装 RealSense SDK |
| 云台随时间漂移 | 机械滑移 | 拧紧支架螺丝，重新校准 |
| 咯吱异响 | 机械卡滞 | 检查线缆干涉，松支架 |
| Python 导入错误 | 缺少依赖 | `pip install -r requirements.txt` |
